# Maison HD — пакет коду бухгалтерії для аудиту

Дата формування: 19 вересня 2026 року.

Це ізольована копія файлів, які формують розділ **«Бухгалтерія»** Maison HD та пов’язані фінансові/фіскальні потоки. Оригінальну структуру шляхів збережено, щоб імпорти та зв’язки між файлами було легко простежити.

## Що входить

- **Frontend:** основна сторінка бухгалтерії, фінанси, рахунки, платежі, нічний аудит, міграція даних, ПРРО, каси, зміни, винятки, юридичні особи, податки та звіти.
- **Backend:** бухгалтерські документи, подвійний запис, журнал проводок, синхронізація, міграція, фінанси, платежі, рахунки, ПРРО та інтеграції з операційними модулями.
- **Фіскальний контур:** оркестрація ПРРО, політики фіскалізації, XML, підписання, ДПС, Checkbox і protobuf-контракт.
- **База даних:** Drizzle-схеми, основна SQL-міграція та runtime-схема сервера.
- **Контракти:** OpenAPI, згенерований клієнт і Zod-типи для фінансових операцій.
- **Конфігурація:** package/TypeScript/Vite/workspace файли, потрібні для розуміння збірки.

## Архітектура

```text
Maison HD /accounting
  ├─ /api/acc/*          → ledger, проводки, звіти, контрагенти, аудит
  ├─ /api/accounting/*   → рахунки, акти, публічні документи, надсилання
  ├─ /api/invoices/*     → готельні рахунки та оплати
  ├─ /api/payments/*     → платіжний контур
  └─ /api/fb/*, /api/prro/*
       → каси, зміни, чеки, ПРРО, фіскальні події

Операційні джерела
  ├─ бронювання / folio
  ├─ ресторан / POS
  ├─ SPA / minibar
  ├─ LiqPay / Poster / Servio / Checkbox
  └─ ручні бухгалтерські документи
       ↓
Подвійний бухгалтерський запис + платежі
       ↓
PRRO orchestrator
  ├─ визначення продавця та політики
  ├─ блокування каси / зміни
  ├─ ідемпотентне створення фіскального документа
  ├─ XML + підпис
  └─ ДПС або Checkbox
       ↓
Статуси, фіскальні події, журнал, звіти та ручна перевірка
```

## Основні точки входу

1. `artifacts/maison-hd/src/pages/accounting.tsx` — головний UI розділу.
2. `artifacts/api-server/src/routes/acc-ledger.ts` — бухгалтерське ядро та подвійний запис.
3. `artifacts/api-server/src/routes/accounting.ts` — рахунки, акти й публічні документи.
4. `artifacts/api-server/src/services/prro-orchestrator.ts` — спільний фіскальний процес.
5. `lib/db/src/schema/accounting.ts` — спільна бухгалтерська схема.
6. `artifacts/api-server/src/index.ts` — runtime-створення частини таблиць; важливо перевіряти разом із SQL-міграціями.

## Основні аудиторські питання

- Чи кожен запит і запис обмежений `organization_id`.
- Чи всі фінансові мутації атомарні та мають правильне блокування.
- Чи дебет завжди дорівнює кредиту та чи є незмінний audit trail.
- Чи платежі та фіскальні документи ідемпотентні при повторних callback/webhook.
- Чи правильно визначається продавець, каса, зміна та юридична особа.
- Чи приватний КЕП не потрапляє в API, логи або базу у відкритому вигляді.
- Чи невизначена відповідь ДПС не спричиняє повторний чек.
- Чи runtime DDL та міграції не розходяться між середовищами.
- Чи публічні посилання на документи підписані, обмежені tenant scope та мають строк дії.

## Межі пакета

Пакет не містить `.env`, секретів, ключів, токенів, `node_modules`, build-артефактів або даних бази. Це пакет вихідного коду для статичного аудиту. Для повного динамічного аудиту окремо потрібні тестове середовище, тестова БД та sandbox-провайдери.

## Файли контролю

- `FILE_MANIFEST.txt` — перелік усіх включених файлів із розмірами.
- `SHA256SUMS.txt` — SHA-256 кожного файла для перевірки цілісності.
- `MISSING_FILES.txt` — очікувані, але відсутні файли (якщо такий файл створено).
